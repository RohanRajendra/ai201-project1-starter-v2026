## Unit 2: The Unofficial Guide (Test)

Total Points: **15pts** + 2pts bonus

Your report lists these in this order, so you can see exactly which ones you earned.

### Required Features

| 4pts | **The test actually ran, with repeated trials** |
|---|---|
| 1 | Your run log is a table with a row for each of your five criteria |
| 1 | **Every** row records three separate run values |
| 1 | Real output from at least one run is pasted as text, not described |
| 1 | That pasted output names the file and function that produced it |

Identical values across your three runs are fine. Retrieval is deterministic, and for your relevance-gate criterion reporting one number in all three columns is what a correct submission looks like.

| 4pts | **Your verdicts, your reasoning, and any revisions** |
|---|---|
| 2 | **At least one** of your verdicts follows from your run log and your target |
| 1 | **Every** verdict carries a sentence on how you decided |
| 1 | Any revision to a criterion is recorded rather than made in place |

Missing a criterion costs nothing: a correct MISSED counts exactly as much as a correct MET. A revision made because you missed the number is not a legitimate revision.

| 4pts | **Every miss is diagnosed** |
|---|---|
| 2 | **Every** miss names one of the five pipeline stages — loading, chunking, embedding, retrieval, generation |
| 2 | **Every** miss states the mechanism: what that stage did to *your* corpus or settings |

Both are all-or-nothing across your misses. If nothing fell short there is nothing to diagnose, so the first 2pts aren't available; you can still earn the second by naming which criterion you'd tighten and the tighter target you'd set.

| 3pts | **The improvement follows from the diagnosis and was measured** |
|---|---|
| 1 | You name the change **and** say which diagnosed failure it was meant to fix |
| 1 | A second run log with a row for each of your five criteria and three run values in every row |
| 1 | You say whether the change helped, with the numbers from both logs |

A change that made things worse, honestly reported with its numbers, earns the third point in full, and so does saying you can't tell if you refer to both logs.

### Stretch Features

Stretch items are all-or-nothing. An item earns its points only if you declared it in your README before you built it, it is present in the repository, and your README accounts for what it changed.

| +2pts | **A second measured improvement** |
|---|---|
| | A second change from the Milestone 4 menu, run and logged the way the first one was: a third run log in the same table format, and a statement of whether it helped. **An improvement that made things worse, honestly reported, earns this in full.** |
